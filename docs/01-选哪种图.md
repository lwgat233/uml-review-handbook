## 2. 全套共用的小例子（定稿）

**例子 = 随笔 App（mark-readnotes）**，也就是本人现在在用的那个记随笔的安卓应用。

> **一句话定位**：看网页、看视频、看论文时随手记的「随笔」App；记下来的东西就是**普通的 markdown 文件**，
> 存在用户自己选的目录里，**文件是唯一权威**，应用只负责记、看、找、导出、同步。

**名词表（后面 14 张图都用这套词，不再换）**

| 名词 | 中文 | 是什么 |
|---|---|---|
| Topic | 主题 | 一条随笔；第一行是一级标题（H1），下面挂若干块 |
| Block | 块 | 随笔里的一行内容；分五类（见下） |
| LinkBlock / QuestionBlock / AnswerBlock / ConceptBlock / ViewpointBlock | 链接块 / 提问块 / 回答块 / 概念块 / 观点块 | 五类块，每块独占一行、行首带编号（编号前缀口径**待确认**，见 P25） |
| Tag | 标签 | 一条随笔可以有多个标签；**第一个标签决定它进哪个文件** |
| Folder | 文件夹 | 标签映射成的文件夹，笔记在磁盘上按它分门别类 |
| NoteFile | 笔记文件 | 一个 `.md` 文件 = 一个标签的内容 |
| IndexDb | 索引库 | 本地 SQLite 索引（块、文件、来源目录），**可重建** |
| NoteStore | 笔记库 | 负责读写文件、搬家、整理旧布局（op 层：`blk.*`、`idx.*`） |
| Exporter | 导出器 | 按标签生成目录树、写盘、系统分享（op 层：`exp.*`） |
| SyncClient | 同步器 | 与自己的网盘（WebDAV）比对基线、上传下载、冲突三选 |
| Home / Board / Sheet / Preview | 主页 / 全屏白板 / 小窗 / 预览 | 界面上的四个位置：列表、编辑、弹出小窗、渲染预览 |
| 用户 | — | 记随笔的人（本人） |

**为什么选它**：本人熟（一上手就能看懂图里在说什么），而且它的结构刚好能撑起 14 张图——
有"东西"（主题/块/标签/文件）、有"容器"（文件夹/目录/网络盘）、有"流程"（编辑→保存→搬家→导出→同步）、有"状态"（索引新鲜/需要刷新、同步冲突）。

## 3. 「选哪种图」对照表（想表达什么 → 用哪张图）

| 我脑子里想表达的是… | 用这张图 | 一句话记法 |
|---|---|---|
| 有哪些种类的东西、它们之间是什么关系（一个主题由哪些块组成） | **类图**（Class Diagram） | 东西的"族谱" |
| 某一时刻具体是哪几个东西、各自什么取值（这条随笔此刻有哪些块） | **对象图**（Object Diagram） | 族谱上"具体的那一家" |
| 代码/模块怎么分组、谁依赖谁（随笔域、存储、界面三层） | **包图**（Package Diagram） | 大箱子套小箱子 |
| 系统由哪几个可替换的大件组成、对外提供什么接口（能换掉的同步器） | **组件图**（Component Diagram） | 拼装积木 |
| 这些东西跑在哪台机器/哪个目录上（手机、NAS、WebDAV 服务器） | **部署图**（Deployment Diagram） | 谁住在哪 |
| 一个东西内部由哪些零件组成、零件怎么连（白板内部） | **组合结构图**（Composite Structure Diagram） | 拆开看内部接线 |
| 实际交付的文件长什么样（`app-debug.apk`、`registry.js`、`plantuml.jar`） | **制品图**（Artifact Diagram） | 打包清单 |
| 谁用它、他能做哪些事（记随笔的人能做哪些操作） | **用例图**（Use Case Diagram） | 用户能干什么 |
| 一件事从头到尾有哪些步骤、哪里分支/并行 | **活动图**（Activity Diagram） | 流程图 |
| 一个东西有哪些状态、什么事件让它变状态（同步的"待同步/冲突/已同步"） | **状态机图**（State Machine Diagram） | 红绿灯 |
| 一次操作里几个角色按时间先后互相说了什么（点保存→写文件→更新索引） | **时序图**（Sequence Diagram） | 通话记录 |
| 同样几方的消息往返，但重点看"谁和谁有连线"而不是时间 | **通信图**（Communication Diagram） | 关系网 + 编号 |
| 把好几个场景串成一张总览（编辑/导出/同步三条流） | **交互概览图**（Interaction Overview Diagram） | 场景目录 |
| 强调"时间轴和时限"（上传 30 秒没动静就超时） | **定时图**（Timing Diagram） | 秒表 |

**一句话选图法**：讲**东西**用结构类（类图最常用），讲**事情**用行为类（流程图用活动图，时间顺序用时序图，用户能干什么用用例图）。

## 4. 每张图的四样（本手册的固定格式）

1. **一句话**：它讲什么、什么时候用；
2. **关键元素**：图里的方框和箭头各代表什么（术语给中文，英文原词括注）；
3. **最小示例**：用第 2 节那个随笔 App，配图；
4. **源与校验**：`src/<名字>.puml` + `figures/<名字>.svg` + `evidence/校验-<轮次>.txt`（语法校验读数，0 error）。

> 说明：本手册用的图都是 PlantUML 画的（源码可 diff、可重建）；类图、用例图这类需要额外布局程序，
> 本机没有，所以源里加了一行 `!pragma layout smetana` 用内置布局——这只影响排版，不影响语法与含义。
